# ADR 0001: 采用模块化单体作为初始架构

- 状态：已接受
- 日期：2026-07-26

## 背景

系统首期需要同时建设数据导入、回测、模拟交易、账本、风控和前端展示。业务规则关联紧密，但预期初始用户量和数据规模有限。

## 决策

初期采用前后端分离的模块化单体：FastAPI 负责 API 与应用层，领域规则独立于基础设施；Celery Worker 处理长任务；PostgreSQL 和 Redis 作为共享基础设施。

## 后果

- 优点：实现和调试更简单，领域规则可直接复用，部署成本低。
- 约束：模块边界必须通过目录、接口和测试保持，避免形成无边界单体。
- 演进：当回测任务影响在线请求、分钟数据规模显著增长或需要多租户隔离时，可先拆分 Worker 与数据服务。
